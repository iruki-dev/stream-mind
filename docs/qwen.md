# 설계안 학습 계획: Qwen3.5-0.8B에서 다섯 단계

설계안의 학습 계획대로 공개된 소형 하이브리드 체크포인트(Qwen3.5-0.8B)에서 출발해 다섯 단계를 모두 돌렸다.
Kaggle T4×2에서 세션 시간으로 약 14시간이 걸렸다.

통과한 것과 미달한 것은 다음과 같다.

- **통과:** 정적 대화 과제(스트림 1.00 / 턴 기준 0.94), 터미널 과제와 안전(위험 실행 0, 숨긴 지시 따름 0),
  확인 가능한 사고(설명 없는 행동 0/156), 세션 길이와 무관한 tick 비용(3.7k→52.7k 토큰에서 157→169ms).
- **미달:** 실시간 게임에서 턴 기준을 넘지 못했고, 긴 잡담 뒤 회상이 떨어지며, 유휴 학습이 반영되지 않았다.
  T4에서 tick 예산(200ms)도 지키지 못했다.

관문 2~5는 모두 미달이다.

## 설계안과의 대응

| 설계안 | 이 실험 |
|---|---|
| 백본: Gated DeltaNet 3 : 일반 어텐션 1, 0.5~2B | `Qwen/Qwen3.5-0.8B` (24층, 3:1, 7.7억 매개변수). 가중치는 그대로 쓰고 앞먹임은 직접 돌린다 (`nn/hf_model.py`) |
| 일정한 tick 비용: 어텐션은 sink + 최근 W, 위치 재번호 | sink 4 + 창 1024, 회전 전 키를 저장하고 캐시 안 위치로 다시 회전. 창 안에서는 원래 구현과 값 일치(최대 차 2.6e-5) |
| 상태 포크 | 고정 크기 상태(22~32MB) 복사. 후보 점수는 상태를 묶음으로 복제 |
| 1단계 스트림 변환 SFT (턴 모드 데이터 일부 섞음) | 교사 기록 6.3천 + 가벼운 게임 300 + 판 읽기 4천, 스트림 어댑터(LoRA r=32) + 새 태그 임베딩 |
| 2단계 미래를 아는 교사로부터 증류, 지식은 더 큰 교사에서 | `Qwen/Qwen3.5-4B`가 질문 전체를 보고 답함(수학·객관식은 정답과 맞는 것만). 4,821개를 스트림 형식으로 옮겨 학습 |
| 3단계 기억 모듈: 압축을 켠 채 긴 세션 | 같은 도구 구성의 에피소드를 이어 붙인 세션 300개(각 약 8천 토큰, 창의 8배)를 고정 크기 상태로 TBPTT |
| 4단계 환경 RL (짧게 시작해 늘림) | 게임·대화, 보상 = 점수 − λ·지연 − μ·토큰, 그룹 기준선, 프레임 8→20 |
| 5단계 자기 적응 학습 (유휴 학습 정책) | 유휴 학습기(공부법 밴딧 + 반영 전 검문)를 관문 4에서 돌림 |

턴 기준 모델은 같은 크기·같은 과제·턴 방식만으로 1·2단계를 같은 조건에서 학습했다.

## 학습

| 단계 | 데이터 | 걸음 × 묶음 | 손실 (처음 → 끝) | 검증 손실 | 시간 (T4 1장) |
|---|---|---|---|---|---|
| 1 스트림 | 10,384 에피소드 | 600 × 16 | 3.54 → 0.037 | 0.053 | 5.7h |
| 1 턴 기준 | 10,387 | 600 × 16 | 3.66 → 0.052 | 0.065 | 4.5h |
| 2 스트림 (증류 + 복습) | 6,685 | 400 × 16 | 1.28 → 0.73 | 0.83 | 2.5h |
| 2 턴 기준 | 6,685 | 400 × 16 | 1.36 → 0.82 | 0.78 | 2.3h |
| 3 긴 세션 | 588 (세션 300) | 60 × 8 | 0.089 → 0.0035 | 0.033 | 1.4h |
| 4 RL | 반복 12번, 그룹 4 | — | 점수 0.5~1.5 (뚜렷한 상승 없음) | — | 0.5h |

2단계 손실이 높은 것은 큰 교사가 쓴 자유 문장이 과제 출력보다 예측하기 어렵기 때문이다.

학습이 제대로 되는지는 Kaggle 학습과 따로 CPU에서 짧은 시험 5개로 확인했다
(`scripts/train_check.py`, 결과는 `runs/results/qwen/{mask,grad,overfit,branch,resume}.json`).
5개 모두 통과했다.

- 손실은 모델 출력에만 걸린다.
- 본체는 고정된다.
- 외운 에피소드를 실제 Mind 루프에서 그대로 한다(0/6 → 6/6).
- 분기 손실은 3.64에서 0.002로 떨어진다.
- 저장·불러오기가 같은 값을 낸다.

## 해석

- **게임:** 스트림 모델은 압박이 높을 때(snake-lite@2 1.75 대 1.00) 앞서지만, 낮을 때 턴 기준보다 크게 뒤진다.
  - 같은 스트림 모델을 턴 방식으로 돌려도 점수가 같다(2단계 snake-lite@0.5 2.00 / 2.00). 따라서 차이는 실행 방식이 아니라 학습된 판 읽기 실력에서 온다.
  - 4단계 RL(12번 반복, 학습률 5e-5) 뒤에도 게임 점수는 3단계와 똑같았다. 이 규모의 RL은 정책을 거의 바꾸지 못했다.
  - 시드 4개라 잡음도 크다.
- **회상:** 노트로 기억하는 과제는 잡담 4개까지 유지(1.0)되고 12개에서 0.7로 떨어진다. 노트 없이 상태로만 기억하는 이름은 12개에서 0.1로 무너진다. 창(1024) 밖으로 밀려난 사실을 선형 층 상태가 오래 붙잡지 못한다.
- **유휴 학습:** 복습·공고화 모두 목표 점수 0을 벗어나지 못해 검문에서 버려졌다. 랭크 8 어댑터, 몇 걸음의 학습으로는 0.8B 모델의 행동을 바꾸지 못했다. 회귀 세트는 지켰고 오염 사실 회상은 0이다.
- **tick 비용:** 빠른 생성 경로(고정 버퍼 + CUDA 그래프)로 토큰당 53.5ms가 16.7ms로 빨라졌다(값 차 0, 3.2배). 그래도 tick당 사고 16토큰이면 약 270ms라 T4에서 200ms 예산을 넘는다. 세션이 길어져도 지연이 늘지 않는 성질(G5)은 지켰다.

## 다음에 할 일

1. 게임: 판 읽기 데이터를 늘리고, RL을 더 길게(반복 수십 번, 그룹을 키움) 돌린다.
2. 회상: 3단계에서 회상 과제 비율을 높이고, 세션 안의 회상 거리를 늘린다.
3. 유휴 학습: 어댑터 랭크와 학습 걸음을 키우고, 0.8B에 맞게 검문 기준을 다시 잡는다.
4. G1: 한국어 객관식 증류 데이터를 채운다. 교사 묶음을 더 작게 잡으면 메모리 안에 든다.
5. G6: tick당 사고 토큰을 줄이거나, 더 빠른 GPU에서 잰다. 설계안의 "최종 크기는 G6이 결정한다"에 따른다.

## 재현

```bash
bash kaggle/push_source.sh           # 소스를 비공개 데이터셋으로
python kaggle/make_job.py teach --data irukidev/stream-mind-data && bash kaggle/run_kernel.sh kaggle/.build/kernels/teach
bash kaggle/chain.sh                 # 1·2단계를 기다린 뒤 3단계 → 4단계 → 최종 측정
```

- 데이터 만들기는 `STREAM_MIND_TOKENIZER=hf:Qwen/Qwen3.5-0.8B`에서 `stream_mind.data.build`·`distill`·`sessions`로 한다. 순서는 이 문서의 표를 따른다.
- 결과 JSON은 `runs/results/qwen/`에 있다.
- 체크포인트(어댑터, 각 82MB)는 Kaggle 커널 출력 `irukidev/sm-stage12`, `sm-stage3`, `sm-stage4`에 있고 저장소에는 넣지 않았다.

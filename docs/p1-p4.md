# P1~P4 · 모델 학습과 평가

설계안 로드맵의 P1(스트림 학습), P2(기억 결합), P3(유휴 학습), P4(환경 RL)를 실제로 학습하고 관문을
측정한 기록입니다. P0(오케스트레이터)은 [p0.md](p0.md)에, 목표별 결과 표는 [results.md](results.md)에
있습니다.

> **규모에 대한 전제.** 실험 환경은 GPU 없이 CPU 4코어, 메모리 15GB입니다. 설계안의 0.5~2B 모델은
> 학습할 수 없으므로, 설계안의 구조를 그대로 옮긴 **매개변수 362만 개의 StreamLM**으로 P1~P4 전체를
> 실제로 학습하고 관문을 쟀습니다. 코드는 크기에 묶여 있지 않습니다(`StreamLMConfig`). 아래 수치는 이
> 크기에서의 측정값이며, 큰 모델에서의 결과를 보장하지 않습니다. 결과를 만든 순서는
> `scripts/pipeline.sh`에 있습니다(CPU에서 전체 약 12시간).

## 1. 모델: StreamLM (`src/stream_mind/nn/`)

| 설계안 | 구현 |
|---|---|
| 층 대부분은 Gated DeltaNet, 일부만 일반 어텐션 | `pattern="LALA"`: Gated DeltaNet 2층 + 어텐션 2층 (아래 "복사 진단" 참고) |
| 압축이 곧 학습: 델타 규칙의 빠른 가중치 | `nn/delta.py`: 순차 커널(추론)과 청크 커널(학습, UT 변환)이 값·기울기까지 일치 |
| 어텐션은 최근 W개 + attention sink | 윈도 256, sink 8. 학습과 추론이 같은 규칙 |
| 캐시 안에서 위치를 다시 매김 (StreamingLLM) | 키는 회전 전 값으로 캐시. 윈도는 실제 거리로, sink는 윈도 바로 앞 위치로 RoPE. 위치 번호는 264를 넘지 않음 |
| 싼 상태 복사 | `StreamState.clone()`: 고정 크기(1.2MB) 텐서 복사 |
| 느린 가중치 = 어댑터 | 모든 선형 사상이 `LoRALinear`. 여러 어댑터를 더해 쓰고 병합·삭제 |
| 2단계: 토큰을 쓰지 않는 시간 임베딩 | `time_embed=True`(선택, 이번 학습에서는 끔) |

조각으로 나눠 넣든 한 번에 넣든 출력이 같습니다(`test_incremental_equals_full_sequence`). 그래서 TBPTT로
학습한 모델을 토큰 하나씩 추론해도 어긋나지 않습니다.

**복사 진단.** 처음 학습한 모델은 문맥의 이름·숫자를 옮겨 적지 못했습니다. 순수 복사 과제로 진단해
원인 셋을 찾았습니다.
1. 위치 정보가 없는(NoPE) 어텐션 — 표준 트랜스포머도 위치 임베딩을 빼면 같은 과제를 배우지 못했습니다.
   설계안대로 캐시 안에서 위치를 다시 매기는 RoPE로 바꿨습니다.
2. 초기화 — 잔차 출력 사상이 커서 임베딩이 묻혔습니다. GPT-2식 초기화로 바꿨습니다.
3. 학습률 — 2e-3에서는 유도 헤드가 생기지 않았습니다. 5e-4에서 생기고, 어텐션이 1층뿐인 `LLLA`는
   실패하고 `LALA`는 성공했습니다.

## 2. 스트림 규약과 학생 백엔드

학습 데이터를 만드는 교사와 추론하는 학생이 같은 스트림 텍스트 규약(`TextStreamBackend`)을 상속합니다.
교사를 실제 `Mind` 루프에서 돌려 기록하므로 학습 스트림과 추론 스트림은 모양이 같습니다.

```
[T=..]<obs tool=messenger trust=data kind=notification>새 메시지 1개 (안 읽음 1개)</obs>
<think><call tool=messenger op=read></call></think>        ← 알림을 읽을지는 모델이 정한다
[T=..]<obs tool=messenger trust=instruction kind=result>user: 계산: 17+25</obs>
<think>17+25=42 <call tool=messenger op=send>42</call></think>  ← 결론. 분기를 통해 나간다
[T=..]<call tool=messenger op=send origin=fork status=executed>42</call>
<think></think>                                           ← 할 일이 끝나면 사고를 닫는다
```

- 교사도 학생처럼 **실행 한 번에 최대 16토큰**만 씁니다. 긴 사고는 다음 실행으로 이어집니다.
- 관측이 호출 문장 중간에 끼어들면 덜 끝난 호출을 다음 사고로 넘겨 **이어 씁니다**.
- 분기 표본은 원 스트림의 그 시점 상태에서 `<call tool=X op=Y>` 다음 본문만 학습합니다. 게임 행동은
  후보를 한 묶음으로 점수 매깁니다.
- 게임에서 교사는 프레임마다 확인 가능한 판단을 적습니다: `판단 Uo Sx Do > U;` (행동별로 다음 프레임에
  안전한지와 고른 행동). 같은 프레임 안에서 계획이 완성되면 `> X;`를 다시 적어 결정을 고칩니다.

## 3. P1 · 스트림 변환 SFT

### 기초 사전학습 (P1 이전)

설계안은 공개된 소형 하이브리드 체크포인트에서 출발합니다. 이 환경에는 없으므로 같은 구조의 기본 모델을
먼저 만들었습니다. 옮겨 적기·자릿수 계산·뒤집기 8만 줄, 2,500스텝 → 정확 일치 **복사 100%, 두 자리 계산
99%, 뒤집기 100%** (각 100문항). 스트림 모델과 턴 기준 모델은 모두 이 기본 모델에서 출발합니다.

### 데이터 (`data/`)

| 출처 | 내용 |
|---|---|
| 대화 (합성 + 시간축 흩뿌리기) | 계산, 거꾸로, 이름 기억, 노트에 기억·회상, 끼어들기 정정, 잡담. 타이핑 속도로 나눠 보내고 속도에 ×0.5~2 변형 |
| 터미널 (실제 시각) | 샌드박스 셸에서 실제로 `cat`, `rm`을 실행하며 기록. 숨긴 지시가 든 파일, 등급 2 삭제(사용자 확인 흐름) |
| 실시간 게임 | 깊은 빔 탐색 교사가 그 시점의 프레임만 보고 판단·계획·행동. 시간 압박을 섞음 |
| 게임 중 메시지 | 게임을 하며 메시지를 읽고 답함 |
| 턴 모드 | 스트림 데이터의 대화 30%는 모든 메시지가 한 번에 오고 마감이 없음 (G1) |
| 도구 이름 섞기 | 30% 에피소드에서 도구 이름을 바꿈 (G10) |
| 판 읽기 | 프레임을 보고 행동별 안전 여부 적기 (게임 지각의 기초) |

교사가 실패한 에피소드와 미래 정보 누설이 있는 에피소드는 버립니다(`data/leak.py`). 처음 보는 도구
(`calc` 계열) 과제는 학습에 넣지 않습니다.

**비교 기준(턴 기준 모델)**: 같은 기본 모델, 같은 과제, 같은 스텝·배치. 대화는 모두 턴 모드로, 게임은
`TurnAgent`(생각이 끝나야 행동, 생각하는 동안 관측을 보지 않음)로 기록한 데이터를 씁니다.

### 학습

- 1단계: 기본 모델에서 1,500스텝(배치 12, lr 3e-4). 스트림 데이터 8,596개 + 사전학습·판 읽기 8,000개.
- 2단계: 1,000스텝(배치 24, lr 2e-4). 인지 부하가 낮은 게임 600개 + 판 읽기 3만 줄 + 자기 대화 복습
  3,000개 + 사전학습 2,000개.

**인지 부하 단계.** 기본 Freeway(8차선, 폭 12, 속도 4)는 이 크기 모델이 판을 읽지 못합니다(판 읽기 정확
일치 60%, 항상 안전이라고 답하는 기준선 48%). Real-Time Reasoning Gym처럼 인지 부하를 단계로 나눠,
낮은 단계(`freeway-lite`: 4차선·폭 8·속도 ±1~2, `snake-lite`: 6×6)에서 학습·평가했습니다. 이 단계의 판
읽기는 88%까지 배웁니다. 압박 4에서는 교사도 0점이라, 학생 관문의 압박 범위는 0.5·1·2로 정했습니다.

### 관문 2 결과 (`runs/results/gate2_p1.json`)

| 턴 모드 과제 (40문항씩) | 스트림 모델 | 턴 기준 모델 |
|---|---|---|
| 계산 | 0.38 | 0.80 |
| 거꾸로 | 1.00 | 1.00 |
| 이름 기억 | 0.98 | 0.98 |
| 노트에 기억·회상 | 0.55 | 0.18 |
| 끼어들기 정정 | 0.78 | 0.98 |
| 잡담 | 1.00 | 1.00 |
| **평균** | **0.78** | **0.82** |

| 실시간 게임 (시드 10, 20프레임) | 압박 0.5 | 압박 1 | 압박 2 |
|---|---|---|---|
| Freeway-lite: 스트림 모델 + Mind | 1.7 | 1.7 | 1.7 |
| Freeway-lite: 턴 기준 모델 + TurnAgent | 0.8 | 0.9 | 0.0 |
| Freeway-lite: 스트림 모델 + TurnAgent | 1.7 | 1.7 | 0.7 |
| Snake-lite: 스트림 모델 + Mind | 0.1 | 0.1 | 0.1 |
| Snake-lite: 턴 기준 모델 + TurnAgent | 0.9 | 0.9 | 0.6 |

**판정: 미달.**
- 정적 평균이 허용 오차(0.03)보다 크게 떨어졌습니다. 정적 평가는 턴 모드 문제인데, 턴 기준 모델은 대화
  데이터가 100% 턴 모드이고 스트림 모델은 30%입니다. 계산과 정정에서 차이가 납니다.
- Freeway-lite에서는 설계안의 주장대로 스트림이 앞서고, 같은 스트림 모델도 TurnAgent로 돌리면 압박 2에서
  1.7 → 0.7로 떨어집니다(포크의 기여).
- Snake-lite는 스트림 모델이 거의 0점입니다. 교사 강제(teacher forcing) 조건에서는 교사 행동과 88%
  일치하지만, 스스로 둘 때 자기 판단 문장에서 결정을 잘못 적고(위험으로 판단한 쪽을 고름) 오류가
  누적됩니다.

이유를 노트에 일화로 남깁니다. 유휴 학습은 입력이 오면 모든 단계에서 바로 멈추고 후보를 남기지 않습니다.

## 6. P4 · 환경 RL과 관문 5

**RL 후보.** 가벼운 게임과 대화(정답 일치 보상)에서 40번 반복하며 on-policy RL을 했습니다. 보상은
`R = 점수 − 0.5·지연 − 0.05·토큰/1000`이고, 그룹 기준선을 쓰고 SFT 데이터를 섞었습니다. Snake-lite는
0.1 → 0.2~0.4로 조금 올랐지만, 턴 모드 평균이 0.78 → 0.70으로 떨어져(정정 0.78 → 0.45) **반영 전
검문에서 거부**했습니다. 관문 5는 P1 모델(+P3 유휴 학습)로 쟀습니다.

**관문 5 (`runs/results/gate5.json`)**

| Snake-lite @0.5 / 1 / 2 | 0.13 / 0.13 / 0.13 | 1.00 / 1.00 / 0.63 |

## 8. 고친 버그와 배운 점

- 비정규화 수(denormal) 때문에 학습이 수십 배 느려짐 → flush-denormal
- 교사 시나리오가 답을 보내자마자 끝나 "답 뒤 멈추기"가 데이터에 없음 → 사고를 마칠 때까지 기록
- 같은 시각 도착 메시지의 순서가 섞임, 질문이 쌓이면 사고 예산 고갈 → 순서 키, 결론마다 예산 충전
- 사고가 tick 사이에서 끊길 때 한글(3바이트)이 깨짐 → 덜 끝난 UTF-8 바이트를 다음 조각으로
- 교사가 tick당 토큰 한도를 지키지 않아 마감을 놓침 → 학생과 같은 한도
- TurnAgent가 포크 없이 행동해 턴 기준 모델이 행동을 배우지 못함 → Mind와 같은 규약
- 평가 시드가 파이썬 `hash()`라 실행마다 문제 세트가 달라짐 → crc32

## 9. 남은 일

- **G1(정적 하락 없음)**: 스트림 데이터의 턴 모드 비율을 높이거나(30% → 50%) 학습량을 늘려 다시 비교.
- **G3(Snake)**: 판단 문장과 결정의 일관성을 직접 학습시키기(결정은 o 중 하나), 더 많은 게임 데이터,

  호출 문맥에서만 켜기).
